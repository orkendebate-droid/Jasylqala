## 1. Где что лежит

| Что | Где |
|---|---|
| Сайт | https://jasylqala.onrender.com (с одной «a»; `jaasylqala…` отдаёт 404) |

**Деплой.** Frontend подхватывает пуш в `main` сам. У `Jasylqala-api` автодеплой 13 ноября
не сработал — его деплоили вручную. После любых правок в `backend/` проверять, что api
пересобрался (Settings → Build & Deploy → Auto-Deploy должно быть «Yes», ветка `main`).
Frontend и backend должны быть собраны с одного коммита, иначе новые кнопки падают с ошибкой.

**Кто что делает.** Команда сама снимает 300 деревьев пилота и собирает фото для обучения
нейросети. Логика приложения — в этом репозитории.

## 2. Что сделано в сессии 13–14 ноября

Пять коммитов поверх `ac32dc0`, все в `main`.

### `30a30e2` — установка приложения отдельно от тяжёлых данных
- В панели «Офлайн-режим» карточка «Установить приложение»: кнопка в Chrome/Android,
  подсказка «Поделиться → На экран Домой» на iPhone (`frontend/src/utils/install.ts`).
- Тяжёлые части качаются по отдельности: база деревьев, нейросеть, карта
  (`downloadOfflinePart` в `frontend/src/offline/bundle.ts`). Статус каждой части хранится
  в `OfflineBundleStatus.parts`.

### `4db9af3` — пилотный квартал
- `GET /api/pilot`: граница квартала (GeoJSON), прогресс к 300, разбивка по видам и состояниям.
  На PostGIS считает через `ST_Contains`, на SQLite — проверкой точки в полигоне.
- На карте: пунктирная граница, кнопка «Пилот», счётчик «N / 300». Считаются только реальные
  (не демо) деревья внутри квартала, включая ещё не отправленные с телефона.
- В форме добавления: подсказка «внутри / вне квартала».

### `89ecc4f` — надёжное сохранение в поле
- Координаты больше не подставляются по умолчанию (раньше забытый GPS молча сохранял дерево
  в центре города). GPS запускается сам, ~20 секунд уточняется, берётся самый точный замер.
  Без координат сохранить нельзя; при точности хуже 15 м — предупреждение.
- Сетевая ошибка, таймаут или 5xx → дерево уходит в очередь на телефоне, а не теряется.
  Ошибки данных (4xx) показываются как раньше.
- Таймауты запросов: 15 с обычные, 45 с загрузка фото (`fetchWithTimeout`, `NetworkError`
  в `frontend/src/api.ts`).
- Если сервер не ответил, приложение раз в 30 с проверяет `/health` и само возвращается
  в онлайн (Render на бесплатном тарифе засыпает).
- Одна отправка очереди за раз; `client_id` один на форму — повторное нажатие не создаёт дубль.

### `2487355` — работа с точкой и исправление записей
- `LocationPicker`: маленькая карта в формах добавления и исправления. Метку можно перетащить
  или нажать на карту. Круг точности GPS, оранжевые точки — уже внесённые деревья.
- Проверка дублей: радиус = точность GPS (5–20 м), список до трёх ближайших деревьев с фото.
- Офлайн-карта: дополнительно масштабы 15–18 для квартала (217 тайлов всего вместо 34).
- `PATCH /api/trees/{id}` и мягкое удаление `DELETE /api/trees/{id}` (колонка `deleted_at`,
  добавляется в существующую базу при старте — `_add_missing_columns` в `database.py`).
- При закрытии задачи можно указать состояние дерева после ухода: паспорт обновляется,
  в журнал пишется «Состояние: слабое → хорошее».
- **Пилотный квартал исправлен:** теперь это 10 микрорайон с настоящим контуром из
  OpenStreetMap (way 327567974, ~46 га). Первый вариант был прямоугольником, ошибочно
  подписанным «4 микрорайон».

### Правило про границу квартала
Полигон продублирован в `backend/app/pilot.py` и `frontend/src/pilot.ts`. Менять оба;
тест `test_pilot_polygon_matches_frontend_copy` падает, если копии разошлись.

## 4. Нейросеть — главный незакрытый пункт ТЗ

**Сейчас настоящей нейросети нет.** `backend/app/services/ml_predictor.py` и
`frontend/src/offline/predictor.ts` считают 5 чисел по фото 64×64 (средние R, G, B, разброс
яркости, «зелёность») и сравнивают с прототипами, вписанными в код руками. Название
`jasylqala-mobilenet-lite-v1` ничему не соответствует. Карагач от ясеня так не отличить,
проценты ничего не значат. После выбора фото подсказка сама подставляет свой первый вариант
в поле «Вид» — его надо проверять глазами.

**Решение ещё не принято.** Обсуждали два пути:

| | Pl@ntNet API | Своя модель |
|---|---|---|
| Работает без интернета | Нет | Да |
| Когда заработает | Сразу, нужен ключ | После сбора фото и обучения |
| Точность | Высокая с первого дня | Зависит от фото |
| Лимиты | Бесплатный тариф, ~500 фото в день (по памяти, сверить на сайте) | Нет |

**Предложенный порядок**
1. Подключить Pl@ntNet через backend: ключ на сервере, из ответа оставлять только 7 видов
   справочника, отдавать три варианта. Нужен ключ с my.plantnet.org в переменные окружения
   `Jasylqala-api`.
2. Снимать 300 деревьев пилота — вид в паспортах проверяет человек. Это и есть размеченный
   набор фото.
3. Дообучить MobileNetV3 на этих фото, экспортировать в ONNX (5–10 МБ), запускать на сервере
   и в телефоне без сети. Кнопка «Нейросеть» в офлайн-панели под это готова.

**Что нужно от команды для своей модели**
- 50–100 фото на вид минимум, лучше 150–200. Дерево целиком, крона, лист крупно, кора;
  разные деревья и освещение.
- Правильный вид на каждом фото.
- Учесть сезон: без листьев карагач, ясень, тополь и акация почти неразличимы.
- Редких видов в пилоте будет мало — доснять отдельно или добрать из iNaturalist.

**Пока нейросети нет** — стоит переименовать подсказку в «предварительную» и убрать
автоподстановку вида, чтобы она не вносила ошибки в паспорта. Не сделано, ждёт решения.

**При встройке настоящей модели:** исключить файл модели из прекеша service worker
(`globPatterns` в `frontend/vite.config.ts`), иначе она будет скачиваться при установке,
а не по кнопке. Добавить порог «не уверен — выберите вручную».

## 6. Как запускать и проверять

```bash
# backend: тесты
cd backend && .venv/Scripts/python -m pytest -q

# frontend: типы, тесты, сборка
cd frontend && npx tsc -b && npx vitest run && npm run build

# локальный запуск (backend на 8000, frontend на 5173 с прокси на /api)
cd backend && .venv/Scripts/python -m uvicorn app.main:app --port 8000
cd frontend && npm run dev
```

Service worker в `npm run dev` выключен. Офлайн-режим проверять через
`npm run build && npm run preview` или на Render.

Проверка в браузере без телефона: поднять backend и frontend локально и управлять headless
Chrome через DevTools Protocol (подмена геолокации, клики, скриншоты). Так проверялся
сценарий из раздела 3.
